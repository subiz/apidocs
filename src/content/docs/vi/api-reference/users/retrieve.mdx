Dùng endpoint này để đọc hồ sơ hiện tại của khách hàng, ví dụ trước khi đồng bộ sang CRM.

## Yêu cầu

Gửi yêu cầu `GET` với ID user Subiz của khách hàng trong đường dẫn. Không có body.

| Tham số | Kiểu | Mô tả |
| --- | --- | --- |
| `uid` (đường dẫn) | string | ID user Subiz, như được trả về khi tạo khách hàng. |

ID phải là ID user Subiz. Giá trị khác, như địa chỉ email, sẽ trả lỗi. Nếu chỉ biết định danh kênh của khách hàng, dùng [Tìm hoặc tạo theo định danh kênh](/docs/vi/api-reference/users/identity).

## Phản hồi

Yêu cầu thành công trả HTTP `200` cùng khách hàng. Một số trường:

```json
{
  "id": "user_example",
  "account_id": "account_example",
  "channel": "facebook",
  "channel_source": "page_example",
  "profile_id": "profile_example",
  "attributes": [
    {
      "key": "fullname",
      "text": "Alex Example"
    },
    {
      "key": "emails",
      "text": "alex@example.com"
    }
  ]
}
```

| Trường | Mô tả |
| --- | --- |
| `id` | ID user Subiz. |
| `attributes` | Dữ liệu khách hàng. Tìm từng thuộc tính theo `key`, không theo vị trí. |
| `channel`, `channel_source`, `profile_id` | Định danh kênh, khi khách hàng đến từ kênh đã kết nối. |
| `created`, `updated` | Dấu thời gian Unix tính bằng mili giây. |

Đọc trường giá trị khớp với kiểu thuộc tính: `text`, `number`, `boolean` hoặc `datetime`. Trường rỗng bị lược bỏ, và đối tượng có nhiều trường hơn ví dụ.

## Yêu cầu HTTP

Thay `YOUR_UID` bằng ID user và `YOUR_ACCESS_TOKEN` bằng token của bạn.
