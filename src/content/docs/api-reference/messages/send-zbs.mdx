## Customize the request

Replace the placeholders and sample values above with your own:

| Value | What to use |
| --- | --- |
| `YOUR_ACCID` | Your Subiz account ID. |
| `YOUR_ACCESS_TOKEN` | Your [Bearer access token](/docs/get-started/authentication). Its agent needs permission to use integrations. |
| `zns_phone` | The recipient's phone number, for example `84912345678`. |
| `zns_template_id` | The ID of your approved template, shown in the Subiz app. |
| `zns_template_data` | Your template's parameter names and values. Replace `customer_name` and `order_code` if your template uses different names. |
| `source_event_id` | Optional. Your reference for this send, returned in `data.message.source_event_id`. |

Keep `type: "message_sent"` and `touchpoint.channel: "zns"` as shown. The API still uses the `zns` spelling for ZBS fields and channel values.

Subiz sends from the Official Account that owns the template. That OA must be connected to Subiz, and your account needs enough credit. Each message Zalo accepts is charged; use your own test phone number while developing.

### Fill in template values

Use the exact parameter names from your approved template. Include all required parameters and respect their length limits. **Every value must be a JSON string**, including numbers and dates:

| Template parameter type | Example value |
| --- | --- |
| `STRING` | `"Jane Doe"` or `"ORD-1001"`. |
| `NUMBER` | `"1000000"` — digits only, without thousands separators or currency. |
| `DATE` | `"20/11/2026"` or `"14:30 20/11/2026"` (`dd/MM/yyyy` or `HH:mm dd/MM/yyyy`). |

The parameter's type comes from the template. For example, use a numeric string for `price` only if your template defines it as `NUMBER`.

## Read the response

HTTP `200` alone does not mean Zalo accepted the message. Check the `ack` item in `data.message.pongs`.

When Zalo accepts the message, it returns a `source_message_id`. Selected response fields:

```json
{
  "account_id": "account_example",
  "touchpoint": {
    "channel": "zns",
    "source": "oa_example",
    "id": "84912345678"
  },
  "data": {
    "message": {
      "source_event_id": "order-1001",
      "pongs": [
        {"type": "ack", "source_message_id": "zalo_message_example"}
      ]
    }
  }
}
```

`touchpoint.source` identifies the sending OA. `touchpoint.id` is the normalized phone number: Subiz keeps only digits and replaces a leading `0` with `84`.

## If sending fails

If Zalo rejects the message, the response is still HTTP `200`. The `ack` item contains `ack_error` (Zalo's original error) and `error` (the [Subiz error](/docs/get-started/errors)). You are not charged. For example, selected fields of the `ack` item:

```json
{
  "type": "ack",
  "ack_error": "{\"error\":-108,\"message\":\"Phone number invalid\"}"
}
```

Common Zalo errors: `-108` means an invalid phone number; `-118` means no Zalo account; `-133` means the template cannot be sent at night (10 PM–6 AM).

Subiz rejects the request before sending if, for example, a phone number or template ID is missing, the template does not belong to your account, the OA is disconnected, or credit is insufficient. See [Errors](/docs/get-started/errors) for HTTP error responses.

Do not retry blindly after a timeout: the message may already have been sent and charged.

## Where the send is recorded

Subiz adds a `zns_sent` event to the customer's activity history, creating the customer from the phone number if needed. This runs in the background, including when Zalo rejects the message. The event records the send attempt; the response above tells you whether Zalo accepted it. A ZBS message is not added to a conversation timeline.
