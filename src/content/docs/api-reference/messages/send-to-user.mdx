## Before you begin

Use a [Bearer access token](/docs/get-started/authentication) for the intended account. Replace all `YOUR_…` placeholders with real identifiers. Mutation requests change real data.

## Choose the channel destination

Use this operation when sending through a customer's channel identity. Unlike [Send Message](/docs/api-reference/messages/send), the body is a `messages` array of events, each with its own touchpoint and message data. The path user ID alone is not a substitute for the event's destination.

| Field | Type | Purpose |
| --- | --- | --- |
| `messages` | array | Candidate message events. |
| `messages[].touchpoint` | object | Channel, source, and external profile ID. |
| `messages[].data.message` | object | Message content. |

Replace all channel placeholders with values from your connected integration. Channel-specific permissions and delivery restrictions still apply.

## Candidate behavior

The inspected service tries candidates in order and returns on the first successful send. This is not a bulk-send endpoint. It can stop on an unsubscribed-user error. Use a single candidate when you intend one destination.

## Result

The service returns an event, not an array of results for all candidates. A successful API call does not prove external delivery. Avoid retrying blindly after timeouts.
