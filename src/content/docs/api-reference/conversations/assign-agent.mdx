## Before you begin

Use a [Bearer access token](/docs/get-started/authentication) for the intended account. Replace all `YOUR_…` placeholders with real identifiers. Mutation requests change real data.

## Set conversation ownership

Use the conversation update endpoint to set the `assignee` to an existing agent ID.

| Field | Type | Purpose |
| --- | --- | --- |
| `accid` (path) | string | Account associated with your token. |
| `cid` (path) | string | Conversation to assign. |
| `assignee` | string | Agent ID that should own the conversation. |

`UpdateConversationInfo` updates the assignee and emits `conversation_assigned` when the value changes. It returns the conversation. Assignment does not itself promise to invite the agent; use [Invite an agent](/docs/api-reference/conversations/invite-agent) when participation is needed.

## Clear an assignment

Use the same route with `?x-fields=assignee` and body `{"assignee":""}`. The field selection is necessary to distinguish clearing a value from omitting it. A changed owner becoming empty produces `conversation_unassigned`.

## Automatic routing is different

The `/4.1/conversations/{cid}/assign` route reruns assignment logic and does not decode a target agent ID. Do not use it to choose a specific agent.
