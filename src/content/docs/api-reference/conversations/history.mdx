## Before you begin

Use a [Bearer access token](/docs/get-started/authentication) for the intended account. Replace all `YOUR_…` placeholders with real identifiers. Mutation requests change real data.

## Read conversation events

This endpoint returns the events from `ListEvents`, not a fabricated messages envelope. Event types can differ; inspect `type` before reading `data.message`.

The request schema supports `limit` and `start_id` query parameters. Confirm the next boundary from your returned events; do not assume an offset or a `next_cursor` field. The caller must have access to the conversation.

## Result

The gateway extracts the service's events array and returns it directly. Keep event identifiers when synchronizing history to avoid duplicates.
