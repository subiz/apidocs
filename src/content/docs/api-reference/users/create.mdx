## Before you begin

Use a [Bearer access token](/docs/get-started/authentication) for the intended account. Replace all `YOUR_…` placeholders with real identifiers. Mutation requests change real data.

## Customer records

A user represents a customer, not a staff agent. The gateway accepts customer attributes and optional channel identity fields.

| Field | Type | Purpose |
| --- | --- | --- |
| `attributes` | array | Attribute entries, such as `{"key":"fullname","text":"Alex Example"}`. |
| `channel` | string | Optional channel identity context. |
| `channel_source` | string | Optional source within the channel. |
| `profile_id` | string | Optional external profile identifier. |

Use configured attribute keys and matching value types. The gateway derives the account from authentication and forwards only these fields to the user service.

## Result

The gateway returns the created user from `CreateUser2`. Store its `id` for subsequent requests. Do not repeatedly create records to update an existing customer; use [Update a user](/docs/api-reference/users/update).
