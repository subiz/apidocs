Use this endpoint to read a customer's current profile, for example before syncing it to your CRM.

## Request

Send a `GET` request with the customer's Subiz user ID in the path. There is no request body.

| Parameter | Type | Description |
| --- | --- | --- |
| `uid` (path) | string | Subiz user ID, as returned when the customer was created. |

The ID must be a Subiz user ID. Other values, such as an email address, return an error. If you only know the customer's channel identity, use [Find or create by channel identity](/docs/api-reference/users/identity).

## Response

A successful request returns HTTP `200` with the customer. Selected fields:

```json
{
  "id": "user_example",
  "account_id": "account_example",
  "channel": "facebook",
  "channel_source": "page_example",
  "profile_id": "profile_example",
  "attributes": [
    {
      "key": "fullname",
      "text": "Alex Example"
    },
    {
      "key": "emails",
      "text": "alex@example.com"
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `id` | Subiz user ID. |
| `attributes` | Customer data. Find each attribute by `key`, not by position. |
| `channel`, `channel_source`, `profile_id` | Channel identity, when the customer came from a connected channel. |
| `created`, `updated` | Unix timestamps in milliseconds. |

Read the value field that matches the attribute type: `text`, `number`, `boolean`, or `datetime`. Empty fields are omitted, and the object has more fields than shown.

The response includes an `ETag` header. It changes when the returned customer data changes, so you can compare it to skip unchanged records.

## HTTP request

Replace `YOUR_UID` with the user ID and `YOUR_ACCESS_TOKEN` with your token.
